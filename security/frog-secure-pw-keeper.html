What the password vault protects—and what it cannot.

Frog Secure PW Keeper is designed as an offline Android password vault. This is a concise, developer-maintained account of its security boundaries, based on the project's security documentation. It is not an independent audit, OWASP certification or guarantee against compromise.

Most important: The app has no master-password recovery. A forgotten password, lost device key or lost encrypted backup can mean permanent loss of access. Keep an independent encrypted backup somewhere safe and remember its password.

What needs protecting?

Stored credentials, the key derived from your master password while the vault is unlocked, locally encrypted vault files, and any manually exported .gpv backups. The relevant risks include a stolen device, someone obtaining a backup file, an app left unlocked, accidentally exposing a copied password, and malicious or compromised software on the same device.

Designed protections

  • PBKDF2-HMAC-SHA256 key derivation: 600,000 iterations, 128-bit random salt, 256-bit derived key.
  • AES-256-GCM encryption, fresh 96-bit nonce, 128-bit authentication tag and authenticated file header.
  • An additional local encryption layer using a non-exportable Android Keystore key. StrongBox is device-dependent, not guaranteed.
  • Zero manifest permissions—including no INTERNET permission—no networking code, accounts, telemetry or ads.
  • Background locking, secure-window display protections, masked values and best-effort clipboard expiry.
  • Manual, password-encrypted export and import through Android's file picker. Automatic Android backup is disabled.

Outside those protections

  • A rooted or compromised device, malicious keyboard, accessibility service, operating system or debugger can expose data while it is in use.
  • Portable encrypted backups are subject to offline password guessing; a weak master password is still risky.
  • Once you explicitly export to a cloud provider, or paste into another app, that destination has its own access and privacy risks.
  • Clipboard clearing, screenshot controls and attempts to clear memory cannot remove every copy on every Android device.
  • Encrypted backups may contain previously deleted credentials. App deletion does not recall older exported files or guarantee physical erasure of flash blocks.
  • A matching APK checksum or valid Android signature cannot establish that source code is free of vulnerabilities.

Validation and open work

The developer's private-source checklist maps tests and code reviews to the OWASP MASVS and MASTG. Local encryption, tamper rejection, manifest permissions and some device lifecycle scenarios have developer-recorded tests. Broader physical-device coverage, cloud/transfer quirks, storage failure, accessibility, clipboard behavior and future KDF migration still merit testing. No third-party assessment is represented as completed or underway.

The app's download page identifies the published APK version, file checksum and its observed signing-certificate fingerprint. The public APK verification documentation explains the scope and limits of separate automated binary checks.
